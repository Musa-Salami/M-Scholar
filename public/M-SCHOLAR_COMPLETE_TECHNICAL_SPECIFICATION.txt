1. EXECUTIVE SUMMARY
================================================================================

M-Scholar is a multi-tenant school management platform designed for primary and
secondary schools. It provides four role-based portals:

  • Super Admin       — Full system governance, user provisioning, school config
  • Account Officer   — Finance: income, expenditure, fees, payroll
  • Class Teacher     — Academic ops: attendance, assessments, parent notes
  • Parent / Student  — Read-only academic & financial visibility + messaging

The system must feel like a premium, highly interactive web application with
fast navigation, real-time updates, polished dashboards, and mobile-responsive
layouts. Backend services expose secure APIs; the frontend is a modern SPA/SSR
app deployed to Firebase Hosting with Cloud Functions or a containerized API.

2. SYSTEM GOALS & SCOPE
================================================================================

IN SCOPE
--------
  ✓ Multi-role authentication with strict RBAC
  ✓ Student information management (profiles, classes, sessions/terms)
  ✓ Fee structures, invoicing, payments, receipts, arrears tracking
  ✓ Income & expenditure ledger with categories and audit trail
  ✓ Staff salary management and payslip generation
  ✓ Daily class attendance register with analytics
  ✓ Continuous Assessment (CA) + end-of-term results
  ✓ Teacher-to-parent notes per student
  ✓ Parent/student portal: attendance, fees, results, notes, messaging
  ✓ PDF/Excel export for receipts, report cards, financial reports
  ✓ In-app + email notifications
  ✓ Super Admin audit logs for all critical actions

OUT OF SCOPE (Phase 1 — defer to Phase 2+)
--------------------------------------------
  ✗ Full LMS (lesson plans, video courses)
  ✗ Biometric/hardware attendance devices (API hooks reserved)
  ✗ Multi-school SaaS billing (architecture supports future tenancy)
  ✗ Mobile native apps (responsive PWA is Phase 1 target)

5. RECOMMENDED TECHNOLOGY STACK
================================================================================

FRONTEND (Highly Interactive, Beautiful UI)
-------------------------------------------
  Framework       : Next.js 15 (App Router, Server Components where beneficial)
  Language        : TypeScript 5.x (strict mode)
  Styling         : Tailwind CSS 4 + CSS variables for theming
  Component Lib   : shadcn/ui (Radix primitives) — accessible, customizable
  Icons           : Lucide React
  Charts          : Recharts + Tremor for dashboard KPI cards
  Forms           : React Hook Form + Zod validation
  Tables          : TanStack Table v8 (sorting, filtering, pagination)
  State           : Zustand (client UI state) + TanStack Query (server cache)
  Animations      : Framer Motion (page transitions, micro-interactions)
  Date/Time       : date-fns + timezone support (school locale)
  PDF Generation  : @react-pdf/renderer (client) + Puppeteer (server reports)
  PWA             : next-pwa for offline attendance draft (teacher)

BACKEND
-------
  Option A (Firebase-native — recommended for mscholar.web.app):
    • Firebase Authentication (email/password + optional Google SSO for staff)
    • Cloud Functions for Firebase (Node.js 20, TypeScript)
    • Firestore for messaging threads & notification fan-out
    • Cloud Storage for receipts, report cards, exports
    • Firebase Admin SDK for custom claims (roles)

  Option B (Enterprise scale):
    • NestJS 11 REST API
    • PostgreSQL 16 + Prisma ORM
    • Redis for session cache & job queues
    • BullMQ for async PDF/email jobs
    • Deploy API on Cloud Run; frontend still on Firebase Hosting

  RECOMMENDATION: Start Option A for speed; abstract data layer so PostgreSQL
  can be introduced when transaction volume exceeds Firestore comfort zone.

DATABASE
--------
  Primary (relational data): PostgreSQL via Supabase OR Neon OR Cloud SQL
  Real-time layer: Firestore collections for messages, notifications
  ORM: Prisma (if PostgreSQL) / Firebase Admin SDK (if Firestore-first)

DEVOPS & QUALITY
----------------
  Version Control : GitHub (dedicated M-Scholar repository)
  CI/CD           : GitHub Actions
  Hosting         : Firebase Hosting → mscholar.web.app
  Monitoring      : Firebase Performance + Sentry
  Logging         : Cloud Logging + structured JSON logs
  Secrets         : GitHub Secrets + Firebase Functions config / Secret Manager

7. MODULE SPECIFICATIONS BY PORTAL
================================================================================

7.1 SUPER ADMIN MODULE
----------------------

7.1.1 User Management
  • Create user with: full name, email, phone, role, optional class assignment
  • Auto-generate temporary password; force change on first login
  • Link Parent user to one or more Student records
  • Link Teacher user to Class(es) and Subject(s)
  • Deactivate/reactivate accounts (soft delete)
  • Bulk import teachers via CSV template

7.1.2 School Configuration
  • School profile: name, logo, address, motto, contact
  • Academic session (e.g., 2025/2026) with start/end dates
  • Terms (1st, 2nd, 3rd) with CA weighting config (e.g., CA1 10%, CA2 10%,
    Exam 80%)
  • Grading scale (A=70-100, B=60-69, etc.)
  • Working days & holidays calendar

7.1.3 Class & Subject Management
  • CRUD classes (e.g., JSS 1A, SS 2 Science)
  • CRUD subjects with codes
  • Assign class teacher and subject teachers

7.1.4 Student Enrollment
  • Student profile: admission no, name, DOB, gender, photo, class, guardian
  • Guardian contact for parent portal linking
  • Promote students to next class (bulk at session end)
  • Transfer / withdraw workflow

7.1.5 System Audit
  • Log: who, what, when, IP, before/after snapshot (JSON diff)
  • Export audit log CSV


7.2 ACCOUNT OFFICER MODULE
--------------------------

7.2.1 Fee Management
  • Define fee categories: Tuition, PTA, Uniform, Exam, Transport, etc.
  • Fee structure per class/session/term
  • Optional discounts & scholarships per student
  • Auto-generate invoices at term start
  • Payment methods: Cash, Bank Transfer, POS, Online (Phase 2)

7.2.2 Payment Recording
  • Record payment against invoice (partial payments supported)
  • Auto-generate unique receipt number: MSCH-{YYYY}-{SEQ}
  • Print/download PDF receipt with school logo & payment breakdown
  • Send receipt email to parent (optional toggle)

7.2.3 Income & Expenditure
  • Income sources: fees, donations, grants, other
  • Expenditure categories: salaries, utilities, supplies, maintenance
  • Attach supporting documents (scanned vouchers)
  • Running balance & monthly summaries

7.2.4 Staff Payroll
  • Staff record: employee ID, designation, bank details, salary grade
  • Salary components: basic, allowances, deductions (tax, pension)
  • Monthly payroll run → generates payslips (PDF)
  • Mark as paid; integrate with expenditure ledger

7.2.5 Financial Reports
  • Fee collection report (by class, term, date range)
  • Outstanding balances / debtors list
  • Income vs expenditure statement
  • Payroll summary
  • Export: PDF, Excel (xlsx)


7.3 CLASS TEACHER MODULE
------------------------

7.3.1 Attendance Register
  • Select class + date (default today)
  • Mark each student: Present | Absent | Late | Excused
  • Optional reason field for absence
  • Submit register (locks after submission; admin can unlock)
  • View historical attendance & export class report
  • Analytics: chronic absenteeism flags (>3 consecutive absences)

7.3.2 Assessment & Results
  • Define CA components per subject (CA1, CA2, CA3, Assignment)
  • Score entry: max score validation, auto-percentage
  • Term exam score entry
  • Auto-compute total, grade, position in class (optional)
  • Publish results (draft → published); parents see only published
  • Generate report card PDF (school template)

7.3.3 Parent Notes
  • Create note: student, title, body, priority (info/warning/urgent)
  • Optional attachment (photo of homework, behavior incident)
  • Parent receives notification; read status tracked
  • Notes immutable after 24h (edit window); audit trail preserved

7.3.4 Messaging
  • Thread per parent-student pair (scoped to class teacher)
  • Real-time message delivery (Firestore listeners)
  • File attachment support (max 5MB)
  • School hours policy banner (configurable by admin)


7.4 PARENT / STUDENT MODULE
---------------------------

7.4.1 Dashboard
  • Student summary card: photo, class, class teacher name
  • Quick stats: attendance %, fee balance, latest result grade
  • Recent teacher notes & unread messages

7.4.2 Attendance View
  • Monthly calendar with status colors
  • Summary: days present, absent, late

7.4.3 Fees & Payments
  • List invoices: amount, paid, balance, due date, status badge
  • Download receipt PDF for each completed payment
  • Payment history timeline

7.4.4 Results & Performance
  • View CA breakdown and term results per subject
  • Trend chart across terms (if historical data exists)
  • Download official report card PDF

7.4.5 Teacher Notes
  • Chronological feed with priority indicators
  • Mark as read

7.4.6 Communication
  • Message class teacher (single thread)
  • Push/email notification on teacher reply

9. REST & REAL-TIME API SPECIFICATION
================================================================================

BASE URL: https://api.mscholar.web.app/v1  (Cloud Functions or Cloud Run)
AUTH: Bearer JWT (Firebase ID token) + custom claims { role, schoolId }

AUTHENTICATION
--------------
  POST   /auth/login              { email, password } → { token, user, role }
  POST   /auth/logout
  POST   /auth/forgot-password    { email }
  POST   /auth/reset-password     { token, newPassword }
  GET    /auth/me                   → current user profile

SUPER ADMIN — USERS
-------------------
  GET    /users                     ?role=&page=&search=
  POST   /users                     Create user + role assignment
  GET    /users/:id
  PATCH  /users/:id                 Update profile / deactivate
  POST   /users/:id/reset-password  Admin-triggered reset
  POST   /users/bulk-import         CSV upload

SUPER ADMIN — ACADEMIC
----------------------
  CRUD   /sessions
  CRUD   /sessions/:id/terms
  CRUD   /classes
  CRUD   /subjects
  POST   /classes/:id/assign-teacher

SUPER ADMIN — STUDENTS
----------------------
  GET    /students                  ?classId=&sessionId=&search=
  POST   /students
  GET    /students/:id
  PATCH  /students/:id
  POST   /students/:id/guardians    Link parent user
  POST   /students/promote          Bulk promote to next class

FINANCE — FEES & PAYMENTS
-------------------------
  CRUD   /fee-structures
  GET    /invoices                  ?studentId=&status=&termId=
  POST   /invoices/generate         Bulk generate for class/term
  POST   /payments                  Record payment → auto receipt
  GET    /payments/:id/receipt      PDF stream
  GET    /reports/fees              ?format=pdf|xlsx

FINANCE — LEDGER & PAYROLL
--------------------------
  CRUD   /income
  CRUD   /expenditure
  GET    /reports/financial-summary
  CRUD   /staff
  POST   /payroll/run               { month, year }
  GET    /payroll/:runId/payslips

TEACHER — ATTENDANCE
--------------------
  GET    /attendance/register       ?classId=&date=
  POST   /attendance/register       Create/update register + records
  POST   /attendance/register/submit  Lock register
  GET    /attendance/report         ?classId=&from=&to=

TEACHER — ASSESSMENTS
---------------------
  CRUD   /assessments               Scoped to teacher's subjects
  POST   /assessments/:id/scores    Bulk score entry [{studentId, score}]

10. AUTHENTICATION, AUTHORIZATION & SECURITY
================================================================================

AUTH FLOW
---------
  1. User submits credentials on /login
  2. Firebase Auth validates; Cloud Function sets custom claims on first login
  3. Frontend reads claims → redirects to role dashboard:
       super_admin    → /admin/dashboard
       account_officer→ /finance/dashboard
       class_teacher  → /teacher/dashboard
       parent/student → /portal/dashboard
  4. API middleware validates JWT on every request
  5. RBAC middleware checks role + resource ownership (e.g., parent → own child)

SECURITY CONTROLS
-----------------
  ✓ HTTPS only (Firebase Hosting enforces TLS)
  ✓ Password policy: min 8 chars, complexity rules
  ✓ Rate limiting on auth endpoints (100 req/min/IP)
  ✓ CSRF protection on cookie-based flows (if used)
  ✓ Input validation via Zod on client + server
  ✓ SQL injection prevention via parameterized queries (Prisma)
  ✓ Firestore security rules: users read only their threads/notifications
  ✓ File upload: type whitelist (pdf, jpg, png), virus scan (Cloud Storage)
  ✓ Audit log for all financial and grade mutations
  ✓ PII encryption at rest (Cloud SQL/Firestore default)
  ✓ Session timeout: 30 min idle (configurable)
  ✓ 2FA optional for Super Admin (Firebase MFA — Phase 2)

FIRESTORE SECURITY RULES (sketch)
---------------------------------
  match /threads/{threadId}/messages/{msgId} {
    allow read, write: if request.auth != null &&
      (request.auth.uid in resource.data.participants);
  }
